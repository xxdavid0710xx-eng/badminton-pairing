# 羽球雙打臨打配對系統 — 設計規格

**日期：** 2026-06-10  
**狀態：** 已確認

---

## 1. 目標與範圍

為羽球球館管理員設計一套「臨打配對」管理工具，支援球員登記、實力分級、自動雙打配對、場地管理與場數紀錄。管理員在單一裝置（電腦或手機）上操作全部功能，球員不需要自己的帳號或裝置。

**不在範圍內：**
- 多裝置同步 / 雲端備份
- 球員自助報到
- 計費 / 收費功能

---

## 2. 技術架構

| 項目 | 決定 |
|------|------|
| 前端 | 純 HTML + CSS + Vanilla JS（無框架、無建置步驟） |
| 資料儲存 | `localStorage`（瀏覽器本機，重整不消失） |
| 部署 | 直接開啟 `index.html`，或放到任意靜態網頁伺服器 |
| 相容性 | 桌機瀏覽器 + 手機瀏覽器（RWD 響應式排版） |

## 3. 資料模型

### Player
```json
{
  "id": "uuid",
  "name": "string",
  "skillLevel": "number (1–20)",
  "gamesPlayed": "number",
  "wins": "number",
  "losses": "number",
  "isPresent": "boolean"
}
```

### Game
```json
{
  "id": "uuid",
  "courtId": "number",
  "team1": ["playerId", "playerId"],
  "team2": ["playerId", "playerId"],
  "startTime": "ISO timestamp",
  "endTime": "ISO timestamp | null",
  "result": "null | 'team1' | 'team2'"
}
```

### AppState
```json
{
  "courtCount": "number",
  "courts": {
    "1": { "team1": ["playerId", "playerId"], "team2": ["playerId", "playerId"], "gameId": "uuid" } | null
  }
}
```
> 等待隊列不需要持久化，每次配對前從所有 `isPresent=true` 且不在場上的球員動態排序產生。

**儲存鍵名：**
- `bm_players` — 所有球員資料陣列
- `bm_games` — 所有場次紀錄陣列
- `bm_state` — AppState（今日場地數 + 等待隊列）

## 5. 功能規格

### 5.1 球員管理
- 管理員可新增、編輯、刪除球員
- 每位球員有：姓名、實力等級（1–20）、累計場數、累計勝負
- 管理員勾選「今日出席」，出席球員才會進入等待隊列
- 每位出席球員旁有**「下課」按鈕**：按下後將球員標記為離場，立即從等待隊列移除；若該球員正在場上打球，完場後才移出（不強制中斷進行中的場次）

### 5.2 場地設定
- 管理員在頂部設定今日開放場地數（1–8 片）
- 場地數可隨時調整

### 5.3 公平輪打隊列
等待隊列在每次配對前動態重新排序（不是固定順序）：

1. **主排序：今日已打場數少的優先**（升冪）
2. **次排序：最近完場時間越早的優先**（升冪，即等待越久排越前）

完場後，4 位球員的 `gamesPlayed +1`，重回等待池，下次配對時依規則重排。

**邊界條件：** 等待人數不足 4 人時，不觸發配對，提示管理員等待更多球員出席。

### 5.4 自動配對演算法
觸發時機：管理員按「自動配對」或有空場地時。

**步驟：**
1. 從公平隊列取出前 N 人（N = 空場地數 × 4，最多取前 8 人組成候選池）
2. 對候選池列舉所有「4 人中取 2v2」組合
3. 計算每位球員的**有效級分**：
   - 基礎：`skillLevel`
   - 勝率修正：若 `gamesPlayed ≥ 5`，依下方表格加減（非累加，取最高段）
4. 選出讓「`|team1_avg − team2_avg|` 最小」的組合
5. 若有多組同分，取隊員等待時間最長的組合
6. 填入空場地，從隊列移除已配對的 4 人

### 5.5 完場流程
1. 管理員在場地卡片按「完場」
2. 彈出：**哪隊贏？**（藍隊 / 綠隊 / 平手）
3. 紀錄 `Game.result`，更新 4 人的 `wins` / `losses`
4. 4 人依排隊規則加回等待隊列尾端（`gamesPlayed +1`）
5. 場地卡片清空，等待下次配對

### 5.6 統計顯示
- 等待區每張球員卡顯示：姓名、等級、累計場數
- 球員管理頁顯示：場數、勝率（wins / gamesPlayed）
- 頂部統計：今日出席人數、場地數、等待人數

## 6. 配對演算法說明（勝率修正機制）

設計原則：手動 `skillLevel` 是主要依據，勝率修正是補充，避免過度自動調整。

| 條件 | 有效級分修正 |
|------|------------|
| `gamesPlayed < 5` | 無修正（樣本不足） |
| `winRate 60–75%` | `+0.5` |
| `winRate > 75%` | `+1.0` |
| `winRate < 40%` | `−0.5`（輸太多稍微降） |

修正值上限：`±2.0`，不超過 `skillLevel` 本身的 ±10%。

## 7. UX 細節

- **響應式排版**：場地卡片在手機上改為單欄堆疊
- **配色**：深色主題，場地用藍/綠隊色區分
- **等待區「下一場」標示**：橘色高亮前 4 人（即將被配對者）
- **場地計時器**：每場自動計時，顯示於場地卡片右上角（可選配）
- **資料匯出**（Phase 2）：可將球員統計匯出為 CSV

## 8. 開發優先順序

**Phase 1（核心功能）：**
1. 球員管理 CRUD + LocalStorage
2. 場地設定 + 儀表板佈局
3. 等待隊列（公平排序）
4. 自動配對演算法
5. 完場流程（記錄勝負）

**Phase 2（優化）：**
- 勝率修正納入配對
- 統計頁面
- CSV 匯出
- 場地計時器
