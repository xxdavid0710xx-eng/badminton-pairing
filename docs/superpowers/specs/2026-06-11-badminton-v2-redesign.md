# 羽球臨打配對系統 v2 — 設計規格

**日期：** 2026-06-11
**前版：** `docs/superpowers/specs/2026-06-10-badminton-pairing-design.md`
**範圍：** UI 全面改版 + 新增球員庫、付款、歷史、配對限制、廣播等功能

---

## 1. 整體架構方向

採用 **B 方案（漸進式擴充）**：保留現有所有 JS 模組邏輯（`queue.js`、`matching.js`、`game.js`、`players.js`、`storage.js`），只重寫 UI 層並擴充資料模型。不引入框架、不增加 build step。

### 1.1 導覽結構

左側固定側邊欄，右側主內容區切換頁面：

| 選單項目 | 路由 key | 說明 |
|---------|---------|------|
| 🏸 配對 | `match` | 主操作頁（預設） |
| 👤 球員庫 | `players` | 常客資料庫 |
| 💰 付款 | `payment` | 時段報名 + 收款紀錄 |
| 📊 歷史 | `history` | 歷次活動紀錄 |
| ⚙️ 設定 | `settings` | 場地數、其他偏好 |

頁面切換：純 JS 顯示/隱藏 `<section>` 區塊，無 router，無 hash。

## 2. 資料模型擴充

### 2.1 Player（擴充）

```js
{
  id: string,           // UUID (既有)
  name: string,         // (既有)
  skillLevel: number,   // 1–20 (既有)
  gamesPlayed: number,  // (既有)
  wins: number,         // (既有)
  losses: number,       // (既有)
  isPresent: boolean,   // (既有)
  pendingLeave: boolean,// (既有)
  lastGameEndTime: string|null, // (既有)

  // ── 新增欄位 ──
  gender: 'M' | 'F',               // 性別，預設 'M'
  matchPreference: 'any' | 'male' | 'female' | 'mixed', // 打法偏好，預設 'any'
  partners: string[],   // 優先搭檔 player ID 列表
  avoidTeam: string[],  // 不同隊（可對打）player ID 列表
  avoidAll: string[],   // 完全迴避（不同場）player ID 列表
  manualQueuePosition: number | null, // 手動拖排後的優先順序（null = 使用自動排序）
}
```

### 2.2 Session（新增）

```js
{
  id: string,          // UUID
  date: string,        // ISO date 'YYYY-MM-DD'
  slots: [             // 今日時段列表
    { label: string, start: string, end: string, unitPrice: number }
  ],
  discounts: {         // 多段折扣，key = 段數
    2: number,
    3: number,
    // ...
  },
  playerSlots: {       // playerId → 報名的 slot index 陣列
    [playerId: string]: number[]
  },
  payments: {          // playerId → 付款狀態
    [playerId: string]: { amount: number, paid: boolean }
  }
}
```

**Storage key：** `bm_sessions`（陣列，最新 session 在最後）

### 2.3 Game（不變）

沿用既有 `createGame` 結構，不修改。

### 2.4 LocalStorage keys

| Key | 內容 |
|-----|------|
| `bm_players` | Player[] |
| `bm_games` | Game[] |
| `bm_state` | 場地狀態 |
| `bm_sessions` | Session[]（新增） |

## 3. 配對頁（🏸 配對）改版

### 3.1 新增球員表單

- 姓名文字輸入
- **等級：滑桿**（`<input type="range" min="1" max="20">`），旁顯示當前數值
- **「立即出席」checkbox 預設勾選**
- 送出後：`addPlayer(name, level)` → 若勾選則立即 `setPresent(id, true)`

### 3.2 場地卡 — 羽球場俯視圖

場地卡改為標準羽球雙打場地俯視設計：

**SVG 場線規格**（在 240×380px 容器內）：
- 外框線：`x=8,y=8` to `x=232,y=372`
- 單打邊線（較細）：`x=46` 和 `x=194`，全高
- 雙打長發球線（底線旁）：`y=22` 和 `y=358`
- 短發球線：`y=134` 和 `y=246`
- 中線：僅在發球區段，**不穿越網前區**
  - 上半段：`x=120`，從 `y=22` 到 `y=134`
  - 下半段：`x=120`，從 `y=246` 到 `y=358`
- 球網：`y=50%`，格狀重複漸層 + 上下邊框線
- 球柱：左右各一個小白色矩形

**球員顯示：**
- 藍隊（上半場）：兩個圓形 token，藍色配色
- 綠隊（下半場）：兩個圓形 token，綠色配色
- 每個 token 顯示：名字、勝率（橘色）
- 右上角小 badge 顯示等級數字
- Token 可拖動（詳見 §3.4）

**場地下方資訊列：**
- 藍隊平均等級 vs 綠隊平均等級
- 「完場 →」按鈕

### 3.3 等待區

- 每張等待卡顯示：名字、等級、勝率（橘色）、累計場數
- 右上角顯示拖動把手圖示 `⠿`
- 下一場上場的卡片用橘色邊框標示

### 3.4 完整拖動功能（Drag & Drop）

支援四種拖動操作，全部使用 HTML5 Drag and Drop API：

| 操作 | 起點 | 終點 | 效果 |
|------|------|------|------|
| 重排等待順序 | 等待卡 | 等待卡之間 | 調整排隊優先順序（覆蓋自動排序） |
| 手動上場 | 等待卡 | 空場地 / 球員位置 | 將球員放入該場地指定隊伍 |
| 換隊 | 場上 token | 對方隊伍區 | 兩人對換或移入 |
| 退場 | 場上 token | 等待區 | 將球員移回等待佇列 |

**手動排序標記：** 若用戶拖動過等待卡，在該球員資料上設 `manualQueuePosition`（數字），`buildWaitingQueue` 優先使用此值排序。

### 3.5 上場廣播

自動配對成功後：

1. **視覺橫幅：** 頂部出現廣播卡，顯示「場地 N — 上場：A & B vs C & D」，帶脈衝發光動畫，5 秒後淡出
2. **語音播報：** Web Speech API `SpeechSynthesisUtterance`，語言 `zh-TW`，朗讀「場地一，上場：A、B 對 C、D」
3. 若有多個場地同時配對，依序朗讀每個場地

## 4. 球員庫頁（👤 球員庫）

### 4.1 頁面結構

頂部搜尋列 + 「＋ 新增常客」按鈕，下方為球員列表。

### 4.2 球員列表項目

每位球員顯示：
- 頭像（取姓名第一字）
- 姓名、等級 badge、勝率（橘色）
- 今日出席狀態（綠點）
- 累計場數、勝/負場次、最後出席日期
- 已設定的配對限制標籤（♥ 搭誰、✕ 迴避誰）
- 操作按鈕：✏️ 編輯、🔗 配對設定

### 4.3 配對設定 Modal（🔗 按鈕開啟）

包含以下設定：

**性別：** ♂ 男 / ♀ 女（影響混雙配對邏輯）

**打法偏好：**
- 不限 / ♂♂ 男雙 / ♀♀ 女雙 / ♂♀ 混雙
- 若當場無法滿足偏好（人數不足），該球員自動跳過不配對，不強制更改偏好

**優先搭檔：**
- 點選其他球員名字切換選中狀態（綠色高亮）
- 配對演算法優先將這些人排在同隊

**迴避設定：**
- 先選迴避類型：「不同隊（可對打）」或「完全迴避（不同場）」
- 再點選球員
- 已設定的限制以標籤顯示，可點 ✕ 移除

## 5. 付款頁（💰 付款）

### 5.1 今日時段設定

管理員建立當天時段：
- 每個時段：開始時間、結束時間、單人單段價格
- 可刪除任一時段
- **多段折扣**：輸入「2 段合計價」、「3 段合計價」等，系統自動套用

### 5.2 球員付款明細表

欄位：球員 | 報名時段 | 應付金額 | 場數 | 狀態

- 「報名時段」欄：各時段 tag，點擊切換報名/未報名，同步更新應付金額
- 應付金額：依報名段數查折扣表計算
- 狀態：「✕ 未付」/ 「✓ 已付」，點擊切換

### 5.3 頂部統計

出席人數 / 已收款 / 未收款 / 本場合計

### 5.4 與 Session 資料同步

付款頁操作即時寫入 `bm_sessions` 當日 session。若無當日 session 則自動建立。

**Session 生命週期：** Session 由管理員手動建立（首次設定時段時觸發），不自動關閉。同一天多次開啟 app 仍沿用同一 session。跨日則自動建立新 session。

## 7. 配對演算法擴充（matching.js）

在現有最佳化邏輯基礎上加入限制過濾：

### 7.1 配對前過濾

給定等待佇列，先濾掉因偏好無法滿足的球員：
1. 計算本輪可用球員的性別分佈
2. 偏好 `male`：需要 4 位男性，否則跳過
3. 偏好 `female`：需要 4 位女性，否則跳過
4. 偏好 `mixed`：需要每隊至少 1 男 1 女，否則跳過
5. 偏好 `any`：不限制

### 7.2 組合評分（新增懲罰項）

在現有 `diff`（隊伍平均等級差）基礎上加：
- 違反 `avoidAll`：任兩人同場 → 此組合**直接排除**
- 違反 `avoidTeam`：兩人同隊 → 懲罰 +10
- 未滿足 `partners`：優先搭檔未同隊 → 懲罰 +1（軟性，非強制）

### 7.3 混雙組合規則

若兩位球員偏好 `mixed`，每隊組成必須是 1男 + 1女。

## 8. 存在的邊界情況

| 情況 | 處理方式 |
|------|---------|
| 偏好衝突導致無法配對 | Toast 提示「人數不足，X 人跳過」|
| 所有 avoidAll 導致無可用組合 | Toast 提示「限制過多，無法配對」|
| 手動拖入場地但人數不足 4 人 | 允許半場狀態（僅顯示，不啟動計時，等補滿再開始） |
| 空白 Session（無時段設定）| 付款頁顯示「尚未設定今日時段」提示 |
| 球員資料舊版無 gender 欄位 | migration：讀取時若無 gender 預設 'M' |
